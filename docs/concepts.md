실습하면서 정리한 핵심 개념입니다. 과정 교재와 ROBOTIS e-Manual을 바탕으로 제 말로 다시 썼습니다.

## TurtleBot3 Burger 구성

| 부품 | 역할 |
| --- | --- |
| SBC (Raspberry Pi) | 로봇 위 리눅스 컴퓨터. 센서 데이터를 ROS 토픽으로 내보내고 Remote PC와 통신 |

## SLAM — Gmapping

- 로봇이 **지도를 만들면서 동시에 그 지도 안의 자기 위치**를 추정하는 문제
- Gmapping은 파티클 필터 기반 SLAM: 파티클마다 "로봇 궤적 + 지도" 가설을 들고, 스캔이 지도와 잘 맞는 파티클에 가중치를 줌
- 로그의 `neff`(유효 파티클 수)가 떨어지면 리샘플링 → 가설이 몇 개로 좁혀졌다는 뜻
- 결과 지도는 점유 격자(occupancy grid): 흰색 = 빈 공간, 검정 = 장애물, 회색 = 미탐색

## 위치 추정 — AMCL

- 이미 있는 지도 위에서 위치만 추정하는 **적응형 몬테카를로 위치 추정**
- `2D Pose Estimate`로 대략적인 시작 위치를 주면 그 주변에 파티클을 뿌림
- 로봇이 움직이며 스캔이 쌓일수록 파티클이 실제 위치로 모이고, 확신이 커지면 파티클 수를 줄임(Adaptive)
- 칼만 필터는 단일 가우시안 가정, 파티클 필터는 여러 후보 위치를 동시에 들고 갈 수 있다는 점이 차이

## 경로 계획 — move_base

| 구성 | 역할 |
| --- | --- |
| Global costmap | 전체 지도 기준 비용 지도. 전역 경로 계획에 사용 |
| Local costmap | 로봇 주변 몇 m만 실시간 센서로 갱신. 갑자기 나타난 장애물 반영 |
| Inflation layer | 장애물 둘레를 로봇 반경만큼 부풀려, 가까울수록 높은 비용 부여 |
| Global planner (NavFn) | 출발점 → 목표점 최단 경로 |
| Local planner (DWA) | 지금 낼 수 있는 속도 범위(Dynamic Window) 안에서 여러 (v, ω)를 시뮬레이션해 가장 점수 높은 속도 선택 |

## 비전 — 차선 인식

1. **내부 보정**: 체커보드 사진으로 렌즈 고유 파라미터 · 왜곡 계수를 구해 어안 왜곡을 폄
2. **외부 보정**: 바닥의 사다리꼴 영역을 위에서 본 직사각형으로 펴는 투영(호모그래피) → Bird's-eye view
3. **차선 검출**: HSV 색공간에서 노란선 · 흰선 범위를 잡아 마스크 → 각 차선을 곡선으로 근사
4. **차선 추종**: 두 차선의 중앙과 화면 중앙의 차이를 오차로 보고 각속도를 조절
